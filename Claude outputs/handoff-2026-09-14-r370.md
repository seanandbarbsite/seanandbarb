## r369 - THE COUNT-UP FLOOR

Sean screenshotted `$145,327` on a credential that should read a much larger
number. I first called it a data error, then called the drop "inherent to the
count-up." Both wrong. It was a mid-animation frame of a counter running from
zero, and it took one line to fix.

**Fix.** Both count-up implementations now start at 94 percent of the target
instead of zero, so no frame can ever display a materially wrong figure.

- Worker, inside the injected counter script:
  `var CFLOOR=0.94; ... var v=target*(CFLOOR+(1-CFLOOR)*e);`
- Page-level counter, identical copy on 86 HTML pages:
  `var cur = Math.round(num * (0.94 + 0.06 * eased));`

**Standing rule from this: a number on screen is never allowed to be wrong, even
for 600ms.** Any animated figure gets a floor.

## r370 - THE BUY-PAGE PATTERN ON THE NINE STATE PAGES

This is the design half that r368 deliberately left out.

**Method.** Rather than eyeballing the buy page, a structural feature diff was
run between `buying-a-home/index.html` and each state page. It found three real
gaps, and the fix ports the buy page's own bytes rather than re-authoring them:

1. **No full-bleed block.** Bands rendered as inset cards with rounded corners
   and a shadow while the buy page runs edge to edge. Ported `sb-buy-fullbleed-2026`
   verbatim as `sb-stx-fullbleed-2026` (717 chars).
2. **No sbcta lead form at all.** Only `relocation/index.html` had one. Ported
   the `.sbcta` CSS (2,745 chars) and `<script id="sbcta-js">` (1,052 chars),
   plus a state-specific heading and sub. Form posts to the standard Apps Script
   endpoint with `source` set to "<State> to Florida Relocation".
3. **No `.sbcta` CSS.**

Plus the three changes already scoped:

- **Hero.** The flat `nyfl-herowrap` text block becomes the gold-edge
  `sb-hero-panel` over the existing hero image, three-level breadcrumb, two CTAs
  (Calculate Your Tax Savings, and a Call Us button that flips to Email Us
  outside 9-6 Eastern). Panel is `scale(.72)`, not the buy page's `.66`, and
  carries no body paragraph, so the 8.6px readability item never applies here.
- **Bands.** Cream sequence remapped to
  `#0A1118 / #F4F2EF / #0F0F11 / #F4F2EF / #06101E / #F4F2EF`, dark bands get
  `sb-dark`.
- **Eyebrows stripped.**

`sb-qa` accordions, the residency steps and the state tax table are untouched by
design. The C1 split FAQ panel is deliberately NOT ported - these pages carry
`sb-qa` on content-heavy sections and the brief was to keep them.

**Parity proof.** Computed values on California matched the buy page byte for
byte:

```
BUY        {"bandRadius":"0px","bandMargin":"0px","bandShadow":"none","bandBorder":"0px",
            "sbctaCard":{"bg":"linear-gradient(-45deg, rgb(11, 15, 23),",
            "border":"rgba(212, 175, 55, 0.55)"},"formInputs":3}
CALIFORNIA  identical
```

Feature diff then reported remaining gaps: 0. Pattern rolled to the other eight.

**Two traps hit while building this, both worth remembering:**

- `<\/script>` written into raw HTML does NOT close a script element. The rest of
  the page became script source and rendered blank. Emit `'</scr' + 'ipt>'`.
- The band rewrite regex dropped the closing `"` on the style attribute, which
  swallowed each following `<h2>`. Append the quote explicitly.
- `.sb-dark` rules are page-local to the buy page, not in `sb-global.css`. They
  are injected per page at `</body>` as `sb-stx-dark-2026` with an `html body`
  prefix for specificity.
